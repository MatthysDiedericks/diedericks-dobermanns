## 2. Client personal data must never enter git

`scripts/output/link-dog-owners-review.json` is generated by `link-dog-owners.mjs` and contains
**client full names** — 113 unresolved dog-to-buyer records. It is currently untracked, and it must
stay that way.

**Why this is not a tidiness issue.** Once personal data is committed it is in the history
permanently, mirrored to GitHub, and cloned onto every machine that ever touches the repo.
Deleting the file later does not remove it — the history still carries it. Under POPIA that is a
disclosure Matt cannot walk back, and it is not the kind of thing anyone notices until it matters.

### Already committed — one file, low severity

`supabase/.temp/linked-project.json` **is tracked in the website repo** and should not be. It holds
Supabase CLI project state, not client data, so there is no privacy problem — but the same
`.gitignore` gap that let it through is the one that would let `scripts/output/` through next.

```bash
git rm --cached supabase/.temp/linked-project.json
```

`git rm --cached` only stops tracking it going forward; it stays in history. **That is acceptable
here** because the contents are not sensitive. **Do not rewrite git history for this** — a rebase
across shared branches is far more dangerous than a stale config blob, and Matt would have to
re-clone. If you find anything genuinely sensitive in history, stop and report it rather than
rewriting.

The app repo already ignores `supabase/.temp` (lines 52–53 of its `.gitignore`) and has no such
tracked file. Confirm that rather than assuming.

### Fix both `.gitignore` files

The website's `.gitignore` covers `/node_modules`, `.next`, coverage and little else. Add — and add
the comments, so the next person knows why:

```gitignore
# Supabase CLI local state
supabase/.temp/
**/supabase/.temp/

# Generated script output — MAY CONTAIN CLIENT PERSONAL DATA. Never commit.
scripts/output/
**/scripts/output/

# Local env
.env
.env.local
```

Check `.env` and `.env.local` are already ignored in both repos. **If either is tracked, stop
immediately and tell Matt** — that is a leaked service-role key, not a hygiene item, and the key
must be rotated before anything else happens.

Add the same `scripts/output/` rule to the app repo.
