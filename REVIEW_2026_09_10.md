## Backup

`scripts/backup-supabase.mjs` **was not safe to rely on.** It carried a hard-coded list of 68 tables. The database now has around 120.

A restore from that backup would have silently lost: pedigrees, quotes and quote items, contract clauses and acknowledgements, every application child row, employees, payslips, the equipment catalogue, breeding plans, matings, campaigns and portal invites.

Rewritten to discover the table list from the live API at run time, so a new table is included the day it is created. It now also fails loudly if any of 19 critical tables is missing or unreadable, rather than finishing quietly with a hole in it.

### Run it — paste into the terminal, from the project folder

```
node scripts/backup-supabase.mjs
```

It writes to `backups/<timestamp>/` — one JSON file per table, plus `all-tables.json` and `manifest.json`. Read the critical-table check at the end before trusting it.

### Then the two parts the script cannot reach

**Files.** Images, videos, pedigree PDFs and contracts live in Supabase Storage, not in any table. Download each bucket from the Supabase dashboard → Storage.

**A physical snapshot.** Supabase dashboard → Database → Backups. That is the one you restore from in a real emergency; the JSON dump is for reading and repairing individual records.

A snapshot of today has also been written into the `project_backups` table, matching the convention from June.
